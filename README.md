# KION Recommender System

Учебный проект рекомендательной системы для онлайн-кинотеатра на основе открытого обезличенного датасета KION.

Цель — пройти путь от исследования данных и простого baseline до двухэтапной рекомендательной системы и сервисной инфраструктуры.

## Текущий статус

Реализованы:

- загрузка и первичный аудит полного датасета;
- временное разбиение на train, validation и test;
- сохранение подготовленных данных в Parquet;
- рекомендации по популярности;
- обработка пользователей без истории через fallback по популярности;
- метрики Recall@K, MAP@K, NDCG@K и покрытие каталога;
- отдельная оценка пользователей с историей и без неё;
- разреженная матрица взаимодействий;
- обучение и оценка ALS с 32 и 64 факторами;
- item-to-item на основе косинусного сходства аудиторий;
- журнал экспериментов;
- автоматические тесты и проверка кода Ruff.

Item-to-item с дополнением по популярности показывает лучшее качество top-10 среди проверенных моделей на validation и покрывает 53.59% каталога train.

Следующий этап — объединение кандидатов популярности, ALS и item-to-item и оценка полноты полученного набора.

Ранжирование, FastAPI, Airflow, MLflow, хранилище рекомендаций и инфраструктура развёртывания пока не реализованы.

## Целевая архитектура

Планируется двухэтапная рекомендательная система:

1. Генерация кандидатов: популярность, ALS и item-to-item.
2. Ранжирование объединённых кандидатов: CatBoost или LightGBM.

Модели сравниваются на едином временном разбиении. Для пользователей без истории используется популярность.

## Протокол offline-оценки

- Оцениваются все пользователи с взаимодействиями в validation.
- Релевантными считаются все объекты, просмотренные пользователем в validation.
- Используется бинарная релевантность: длительность и процент просмотра не влияют на метрики.
- Объекты, просмотренные в train, исключаются из рекомендаций.
- Объекты validation, отсутствующие в train, остаются в целевых просмотрах.
- Recall, AP и NDCG считаются для каждого пользователя и усредняются с одинаковым весом.
- Warm — пользователи с историей в train.
- Cold — пользователи без истории в train. Это не обязательно недавно зарегистрированные пользователи.

### Метрики

- **Recall@K** — доля релевантных объектов, найденных среди первых K рекомендаций.
- **MAP@K** — среднее AP@K по пользователям. AP суммирует точность на позициях уникальных попаданий и делит результат на `min(число релевантных объектов, K)`.
- **NDCG@K** — сумма весов уникальных попаданий, нормированная на идеальный список. Вес позиции равен `1 / log2(position + 1)`.
- **Coverage@K** — число уникальных объектов во всех списках top-K, делённое на размер каталога train.

## Матрица взаимодействий

Матрица строится только по train в разреженном формате CSR:

- строки соответствуют пользователям;
- столбцы соответствуют объектам;

## ALS

Реализована модель implicit ALS на бинарной матрице взаимодействий train.

Для пользователей с историей применяются рекомендации ALS с исключением просмотренных объектов. Для пользователей без истории используется популярность.

### Текущая конфигурация

- factors: 64;
- regularization: 0.1;
- iterations: 15;
- alpha: 20.0;
- random_state: 42;
- num_threads: 4;
- обучение на CPU.

Обучение:

```bash
OPENBLAS_NUM_THREADS=1 uv run python -m kion_recs.models.als
```

Оценка:

```bash
OPENBLAS_NUM_THREADS=1 uv run python -m kion_recs.evaluate_als
```

Префикс `OPENBLAS_NUM_THREADS=1` ограничивает число внутренних потоков OpenBLAS для запуска.

Текущие скрипты сохраняют и читают модель из `artifacts/als_f64`. Повторное обучение перезаписывает файлы в этой папке.

```text
artifacts/als_f64/
├── model.npz
├── train_interactions.npz
├── user_ids.parquet
└── item_ids.parquet
```

Соответствия ID необходимы для перевода внутренних индексов в исходные идентификаторы KION. Модель, матрица и соответствия должны относиться к одному запуску обучения.

Оценка вычисляет рекомендации пакетами по 256 пользователей.

### Эксперименты ALS

- [ALS, 32 фактора](experiments/als_baseline.md)
- [ALS, 64 фактора](experiments/als_f64.md)

Первый эксперимент использовал `factors=32` при остальных тех же параметрах. Его артефакты сохранены локально в `artifacts/als`.

Для повторения первого эксперимента текущий код требует изменить число факторов и согласованно задать папку артефактов в обучении и оценке. Выбор конфигурации через командную строку пока не реализован.

Время обучения на локальном компьютере:

- 32 фактора — 21.03 секунды;
- 64 фактора — 97.72 секунды.

Обе конфигурации уступили популярности по точности top-10, но расширили покрытие каталога. Увеличение числа факторов не улучшило качество.

Причина отставания ALS пока не установлена. Результаты не позволяют однозначно объяснить его переобучением.

## Item-to-item

Объекты сравниваются по косинусному сходству их аудиторий в train:

```text
similarity(A, B) = общие зрители / sqrt(зрители A × зрители B)
```

Для каждого объекта сохраняется до 50 соседей с положительным сходством. Сам объект исключается.

Балл кандидата для пользователя — сумма сходств с просмотренными объектами. Просмотренные объекты исключаются из выдачи.

Если кандидатов меньше десяти, список дополняется популярностью без повторов. Для пользователей без истории используется популярность.

### Запуск

Посмотреть похожие объекты с названиями:

```bash
OPENBLAS_NUM_THREADS=1 uv run python -m kion_recs.item_to_item_demo
```

Построить матрицу соседей:

```bash
OPENBLAS_NUM_THREADS=1 uv run python -m kion_recs.train_item_to_item
```

Оценить рекомендации:

```bash
OPENBLAS_NUM_THREADS=1 uv run python -m kion_recs.evaluate_item_to_item
```

Артефакты сохраняются в:

```text
artifacts/item_to_item_k50/
├── neighbors.npz
├── train_interactions.npz
├── user_ids.parquet
└── item_ids.parquet
```

Повторное построение перезаписывает файлы в этой папке.

Сходство вычисляется пакетами по 128 объектов. После отбора top-50 матрица соседей может быть несимметричной.

Для текущего train:

- объектов: 15 415;
- сохранённых связей: 717 297;
- время построения на локальном компьютере: 7.93 секунды.

Время зависит от оборудования и условий запуска.

## Сравнение моделей на validation

ALS и item-to-item используют популярность для Cold-пользователей. Item-to-item также дополняет популярностью неполные списки для Warm.

### Все пользователи

| Модель | Recall@10 | MAP@10 | NDCG@10 | Coverage@10 |
|---|---:|---:|---:|---:|
| Популярность | 0.233721 | 0.120658 | 0.162907 | 0.23% |
| ALS, 32 фактора | 0.206752 | 0.103959 | 0.142205 | 5.25% |
| ALS, 64 фактора | 0.187991 | 0.094631 | 0.129279 | 8.56% |
| Item-to-item, 50 соседей | **0.240284** | **0.121877** | **0.166211** | **53.59%** |

### Пользователи с историей

| Модель | Recall@10 | MAP@10 | NDCG@10 |
|---|---:|---:|---:|
| Популярность | 0.167605 | 0.080656 | 0.115445 |
| ALS, 32 фактора | 0.126388 | 0.055135 | 0.083807 |
| ALS, 64 фактора | 0.097717 | 0.040879 | 0.064052 |
| Item-to-item, 50 соседей | **0.177635** | **0.082518** | **0.120494** |

Item-to-item улучшил Recall@10 относительно популярности примерно на 2.8% по всем пользователям и на 6.0% среди Warm-пользователей.

Cold-метрики совпадают во всех вариантах, поскольку используется один рейтинг популярности.

Результаты получены на одной validation-неделе. Статистическая неопределённость и устойчивость на других временных окнах пока не оценены. Test не используется для выбора моделей и параметров.

## Ограничения текущей версии

Проект представляет собой offline-прототип. Production-инфраструктура находится в плане развития.

Параметры экспериментов задаются в коде. Журнал результатов ведётся вручную, MLflow пока не подключён.

Текущие модели не учитывают возрастные ограничения, доступность контента и метаданные пользователей и объектов при формировании рекомендаций. Названия объектов используются только для демонстрации.

Отсутствие просмотра не является доказательством отсутствия интереса. Offline-оценка основана на наблюдавшихся взаимодействиях и не устраняет смещение исторических показов.

Рост покрытия сам по себе не доказывает улучшение рекомендаций. Улучшение offline-метрик также не гарантирует роста продуктовых показателей — для этого потребуется A/B-тест.
