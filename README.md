# KION Recommender System

Production-oriented рекомендательная система на основе открытого обезличенного датасета онлайн-кинотеатра KION.

## Цель проекта

Построить воспроизводимую двухэтапную рекомендательную систему:

1. Сгенерировать кандидатов с помощью популярности, ALS и item-to-item модели.
2. Отранжировать кандидатов с помощью градиентного бустинга.
3. Оценить качество на временном разбиении без утечки будущих данных.
4. Подготовить систему к запуску в production.

## Датасет

В проекте используется открытый [KION Dataset](https://github.com/irsafilo/KION_DATASET):

- около 5,5 млн взаимодействий;
- около 962 тыс. пользователей;
- около 15 тыс. объектов.

Исходные данные не хранятся в этом репозитории.

## Данные

Инструкция по загрузке находится в [data/README.md](data/README.md).

После загрузки датасета запустите базовую проверку:

```bash
uv run python -m kion_recs.data.audit
```

Проверка валидирует обязательные колонки и выводит размер датасета, количество пользователей, количество объектов и временной диапазон.

## Модель популярности

Объекты ранжируются по числу уникальных пользователей в train.
При равных значениях используется сортировка по item_id.

Уже просмотренные объекты исключаются из рекомендаций.
Для новых пользователей используется общий рейтинг популярности.

Запуск:

```bash
uv run python -m kion_recs.models.popularity
```

Результат сохраняется в `artifacts/popularity.parquet`.

## Оценка популярности на validation

Запуск:

```bash
uv run python -m kion_recs.evaluation
```

Протокол оценки:

- модель обучается только на train;
- оцениваются все пользователи с взаимодействиями в validation;
- просмотренные в train объекты исключаются из рекомендаций;
- Recall@10 считается для каждого пользователя, затем усредняется;
- cold-start означает отсутствие взаимодействий пользователя в train.

|| Группа | Пользователи | Recall@10 | MAP@10 | NDCG@10 |
|---|---:|---:|---:|---:|
| Все | 160 794 | 0.233721 | 0.120658 | 0.162907 |
| С историей в train | 105 212 | 0.167605 | 0.080656 | 0.115445 |
| Без истории в train | 55 582 | 0.358873 | 0.196379 | 0.252749 |

Coverage@10: 36 / 15 415 ≈ 0.002335 (0.23%).

Покрытие считается как число уникальных объектов во всех списках
рекомендаций, делённое на число уникальных объектов в train.

MAP@K — среднее AP@K по пользователям.
Для AP@K используется знаменатель min(число релевантных объектов, K).

NDCG@K использует бинарную релевантность и логарифмическое
снижение веса позиции: 1 / log2(position + 1).

Все три метрики качества усредняются по пользователям с одинаковым весом.
Test пока не используется для оценки.
