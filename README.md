# KION Recommender System

Учебный проект двухэтапной рекомендательной системы для онлайн-кинотеатра на основе открытого обезличенного датасета KION.

Проект охватывает подготовку данных, генерацию кандидатов, ранжирование и offline-оценку. Сервисная и production-инфраструктура находятся в плане развития.

## Текущий результат

Реализованы:

- аудит данных и временные разбиения;
- популярность, ALS и item-to-item;
- объединение кандидатов;
- подготовка обучающих примеров без использования будущих просмотров в генераторах и признаках;
- пакетная генерация полного обучающего набора;
- обучение CatBoostRanker;
- оценка двухэтапной системы на validation;
- Recall@K, MAP@K, NDCG@K и coverage;
- отдельные результаты Warm и Cold;
- парный bootstrap прироста Recall@10;
- журнал экспериментов;
- автоматические тесты и Ruff.

На полном validation двухэтапная система улучшила Recall@10 относительно item-to-item примерно на 14.4%, MAP@10 — на 8.6%, NDCG@10 — на 10.5%.

Абсолютный прирост Recall@10 составил 3.466 процентного пункта. Пользовательский парный bootstrap дал 95%-й percentile-интервал от 3.345 до 3.584 процентного пункта.

Покрытие каталога снизилось с 53.59% до 5.27%.

Результаты относятся к фиксированным моделям и одной validation-неделе. Проверка не учитывает выбор решений по validation и не доказывает продуктовый эффект. Test остаётся нетронутым.

## Архитектура

1. Генерация до 100 кандидатов от каждого источника:
   - популярность;
   - ALS с 32 факторами;
   - item-to-item с 50 соседями на объект.
2. Исключение просмотренного и объединение повторов.
3. Расчёт признаков по доступной истории.
4. Ранжирование CatBoostRanker.
5. Выбор top-10.

Для пользователей без истории кандидаты формируются по популярности. Ранжировщик может изменить их порядок.

FastAPI, Airflow, MLflow, хранилище рекомендаций, Docker Compose и CI/CD пока не реализованы.

## Протокол оценки

- Оцениваются все пользователи с взаимодействиями в validation.
- Релевантность бинарная: объект просмотрен в целевом периоде или нет.
- Длительность и процент просмотра не влияют на метрики.
- Просмотренные в истории объекты исключаются.
- Целевые объекты, отсутствующие в истории, остаются в знаменателе Recall.
- Пользователи получают одинаковый вес при усреднении метрик.
- Warm — пользователи с историей до границы оценки.
- Cold — пользователи без такой истории.
- Пользователи без положительных кандидатов не исключаются из оценки.

### Метрики

- **Recall@K** — доля релевантных объектов, найденных среди первых K рекомендаций.
- **MAP@K** — среднее AP@K по пользователям. AP суммирует точность на позициях уникальных попаданий и делится на `min(число релевантных объектов, K)`.
- **NDCG@K** — сумма весов уникальных попаданий, нормированная на идеальный список. Вес позиции: `1 / log2(position + 1)`.
- **Coverage@K** — число уникальных рекомендованных объектов, делённое на размер каталога истории.
- **Candidate Recall** — полнота всего набора кандидатов, усреднённая по пользователям. Порядок кандидатов не учитывается.

### Item-to-item

Косинусное сходство рассчитывается по совместной аудитории:

```text
similarity(A, B) = общие зрители / sqrt(зрители A × зрители B)
```

Сохраняются до 50 положительных соседей на объект. Сам объект исключается.

Балл кандидата — сумма сходств с просмотренными объектами.

```bash
OPENBLAS_NUM_THREADS=1 uv run python -m kion_recs.item_to_item_demo
OPENBLAS_NUM_THREADS=1 uv run python -m kion_recs.train_item_to_item
OPENBLAS_NUM_THREADS=1 uv run python -m kion_recs.evaluate_item_to_item
```

Артефакты: `artifacts/item_to_item_k50`.

Для основного train:

- объектов: 15 415;
- связей: 717 297;
- время построения: 7.93 секунды.

Сходство вычисляется пакетами по 128 объектов. После отбора соседей матрица может быть несимметричной.

При оценке готового top-10 неполные списки дополняются популярностью. Это потребовалось двум Warm-пользователям. Для Cold используется популярность.

### Разметка и признаки

Для пары «пользователь — кандидат»:

- `target=1`, если объект просмотрен 2–8 августа;
- `target=0`, если наблюдавшегося просмотра в этом периоде нет.

Ноль не означает доказанную неприязнь.

Целевые объекты, отсутствующие среди кандидатов, искусственно не добавляются. Повторные целевые пары учитываются один раз.

Используются девять числовых признаков:

| Признак | Описание |
|---|---|
| `rank_popularity` | Позиция в популярности |
| `rank_als` | Позиция у ALS |
| `rank_item_to_item` | Позиция у item-to-item |
| `n_sources` | Число источников |
| `user_n_items` | Число уникальных просмотренных объектов |
| `user_days_since_last_watch` | Полные дни от последнего просмотра до cutoff |
| `item_n_users` | Число уникальных зрителей |
| `item_n_users_7d` | Уникальные зрители за последние 7 дней истории |
| `is_cold_user` | Отсутствие пользователя в истории |

Для обучения cutoff — 2 августа. Семидневное окно включает 26 июля — 1 августа.

- объединённые кандидаты, отсортированные CatBoost.

Оцениваются все пользователи, включая группы без положительных кандидатов. CatBoost также сортирует популярные кандидаты Cold-пользователей.

Проверяются соответствие генераторов истории validation и порядок признаков.

```text
artifacts/ranker_evaluations/run_.../
├── user_metrics.parquet
└── summary.json
```

Полная оценка первого ранжировщика:

```text
artifacts/ranker_evaluations/run_1gv__v99
```

Названия папок автоматически меняются при повторных запусках. В командах нужно подставлять пути своего запуска.

Для оценки нужны артефакты ALS с 32 факторами и item-to-item, обученные по основному train до 9 августа.

## Парный bootstrap Recall@10

Для каждого пользователя рассчитывается:

```text
difference = Recall@10_ranker − Recall@10_baseline
```

Пользователи сопоставляются по `user_id`. Проверяются одинаковые наборы пользователей, отсутствие повторов и совпадение Warm/Cold.

Параметры:

- пользователь — единица ресэмплинга;
- выборка с возвращением;
- 2 000 повторов;
- random_state: 42;
- percentile-интервал: 95%;
- отдельный расчёт для каждой группы.

```bash
uv run python -m kion_recs.bootstrap_ranker --evaluation-dir artifacts/ranker_evaluations/run_1gv__v99 --n-bootstrap 2000
```

Обучение и генерация рекомендаций не повторяются. Используется `user_metrics.parquet`.

Результат сохраняется в `bootstrap_recall.json` внутри папки оценки. Повторный запуск перезаписывает этот файл.

### Результаты

| Группа | Прирост Recall@10 | Нижняя граница | Верхняя граница |
|---|---:|---:|---:|
| Все | 0.034656 | 0.033447 | 0.035837 |
| Warm | 0.036490 | 0.034872 | 0.038067 |
| Cold | 0.031185 | 0.029243 | 0.033209 |

В процентных пунктах:

| Группа | Прирост | 95%-й интервал |
|---|---:|---|

Во всех группах интервалы находятся выше нуля. Это поддерживает вывод о положительном приросте для фиксированных моделей на рассматриваемой неделе при выбранной схеме ресэмплинга.

Интервалы не являются одновременными для всех групп.

Анализ выполнен после просмотра результатов и не является независимой подтверждающей проверкой. Он не учитывает выбор решений по validation, переобучение моделей, изменение временного периода и возможные зависимости между пользователями.

## Ограничения

Проект является offline-прототипом. Production-инфраструктура пока не реализована.

Часть конфигурации задаётся в коде. Результаты экспериментов записываются вручную. MLflow не подключён.

Первый ранжировщик обучен на выборке пользователей. Его настройки не являются результатом полного поиска гиперпараметров.

Возрастные ограничения, доступность контента и метаданные пользователей и объектов при выдаче не учитываются. Названия используются для демонстрации.

Отсутствие просмотра не доказывает отсутствие интереса. Оценка по историческим взаимодействиям не устраняет смещение исторических показов.

Обучающие и оценочные пользователи выбираются среди имевших просмотры в соответствующем целевом периоде. Это не вся пользовательская база.

Результаты получены на одной validation-неделе. Bootstrap не заменяет проверку устойчивости во времени и независимую итоговую оценку.

Test остаётся нетронутым. Улучшение offline-метрик не гарантирует роста продуктовых показателей — для этого потребуется A/B-тест.
