# Парный bootstrap прироста Recall@10

## Цель

Оценить неопределённость разницы Recall@10 между:

- baseline: item-to-item с дополнением популярностью;
- двухэтапной системой: объединённые кандидаты и CatBoostRanker.

Исходный эксперимент: [первый ранжировщик](ranker_pairlogit_20k.md).

## Данные и метод

Используются сохранённые метрики полного validation за 9–15 августа 2021 года.

Для каждого пользователя вычисляется:

```text
difference = Recall@10_ranker − Recall@10_baseline
```

Пользователи сопоставляются по user_id. Проверяются одинаковые наборы пользователей, отсутствие повторных строк и совпадение Warm/Cold.

Параметры:

- метод: парный непараметрический bootstrap;
- единица повторной выборки: пользователь;
- выборка с возвращением;
- размер повторной выборки равен размеру анализируемой группы;
- число повторов: 2 000;
- random_state: 42;
- интервал: percentile, 95%.

Для каждой группы bootstrap выполняется отдельно.
Интервалы не являются одновременными интервалами для всех групп.

Модели не переобучаются, рекомендации повторно не генерируются.

## Вывод

Во всех трёх группах интервалы абсолютного прироста находятся выше нуля.

Это поддерживает вывод о положительном приросте для фиксированных моделей на рассматриваемой validation-неделе при выбранной схеме ресэмплинга.

## Ограничения

Анализ выполнен после просмотра результатов и не является независимой подтверждающей проверкой.

Bootstrap по пользователям не учитывает:

- изменение качества на других временных периодах;
- неопределённость из-за переобучения моделей;
- выбор моделей и решений по validation;
- возможные зависимости между пользователями;
- продуктовый эффект.

Сравнение отражает совместный эффект объединения кандидатов и ранжирования. Отдельный вклад CatBoost при фиксированном наборе кандидатов не изолирован.

Test остаётся нетронутым.

## Воспроизведение

Для сохранённой полной оценки:

```bash
uv run python -m kion_recs.bootstrap_ranker --evaluation-dir artifacts/ranker_evaluations/run_1gv__v99 --n-bootstrap 2000
```

Вход: user_metrics.parquet и summary.json внутри папки оценки.

Выход: bootstrap_recall.json в той же папке.

Название папки оценки автоматически формируется при запуске. При повторении эксперимента нужно подставить путь к своей полной оценке.

Повторный bootstrap-запуск перезаписывает bootstrap_recall.json.
